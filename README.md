**ChatGPT on Windows 98.**
**在 Windows 98 上直接跑 ChatGPT。**

A native 32-bit Win32 AI chat client for Windows 9x. One ~400 KB EXE completes
a TLS 1.2 handshake on a Pentium and talks to OpenAI-compatible APIs directly —
no relay PC, no proxy, no patched system libraries, no Linux box in the corner.
一个约 400 KB 的原生 Win32 程序，在 Pentium 上完成 TLS 1.2 握手，直连
OpenAI 兼容 API —— 不需要中转机、不需要代理、不改造系统库。

> **[Download the latest release](https://github.com/hsbaoyin/windows98-chatgpt/releases/latest)**
> — unzip into `C:\AGENT98`, edit `AGENT98.INI`, run `AGENT98.EXE`.

## English

### Why this exists

Most "AI on retro hardware" projects end the same way: a Raspberry Pi in the
corner does the HTTPS and the old machine runs a terminal. That is not a
Windows 98 app, it is a thin client with extra steps.

Agent98 does the whole job on the 9x machine. DNS, TCP, a TLS 1.2 handshake
with ECDHE and AES-GCM, chunked HTTP, SSE streaming, JSON parsing and the
agent loop all run inside one 32-bit process on top of Winsock 2 and BearSSL.
Point it at any OpenAI-compatible endpoint and a Pentium II can hold a
conversation.

### Highlights

- C / Win32, built with OpenWatcom 2.0
- BearSSL 0.6 (TLS 1.2, bundled Mozilla trust anchors)
- cJSON
- Console client `a98.exe` and native GUI `agent98.exe` sharing one `agent98.ini`
- OpenAI-compatible Chat Completions API, streaming and non-streaming
- Local tools: read file, write file, list directory, search files, run command
  (writes and shell commands require confirmation)
- Automatic runtime environment block injected into the prompt (Windows version,
  workspace, 16-bit `COMMAND.COM` constraints)

### Release files

`dist/` contains prebuilt Windows 9x binaries:

| File | Description |

### Building

Extract OpenWatcom to `tools/openwatcom/ow`, or set `WATCOM` to the install
directory.

```bat
build_ow.cmd          :: CLI + GUI
build_ow.cmd gui      :: GUI only
build_ow.cmd probe    :: TLS probe
build_ow.cmd clean
```

Artifacts:

- `build/ow/a98.exe` — console client
- `build/ow/agent98.exe` — GUI client
- `build/ow/tlsprobe.exe` — TLS connectivity probe

After adding or removing source files under `src`, regenerate the build rules:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gen_ow_build.ps1
```

#### Multithreaded runtime (important)

The GUI worker thread calls the C runtime (malloc, stdio, logging, ...).
OpenWatcom must use the multithreaded runtime, and new threads must be created
through the CRT:

- compile with `-bm` (see `PROJECT_CFLAGS` in `ow/rules.mk`)
- use `_beginthreadex()`, never `CreateThread()` directly

Otherwise the CRT does not initialise per-thread data for the new thread and
heap operations crash at random (`0xC0000005`, usually inside
`__MemAllocator`).

#### Win9x link options

Every wlink response file generated by `tools/gen_ow_build.ps1` contains:

```
option offset=0x400000
option norelocs
option version=4.0
option stack=262144
```

A fixed base address, no relocation table and image version 4.0 are what the
Windows 9x PE loader accepts; the 256 KB stack leaves room for the BearSSL
client context. After changing these options, re-run
`tools\gen_ow_build.ps1` and do a full `build_ow.cmd clean` rebuild.

#### Startup log

The very first thing `agent98.exe` and `a98.exe` do is open `agent98.log` next
to the executable, record the version and executable directory, and only then
read the INI. When diagnosing a startup crash, look at this file first: if it
was not created at all, the program never reached `main` / `WinMain`.

### Configuration

On first run `agent98.ini` is created next to the executable:

```ini
[api]
base=https://api.openai.com/v1
key=sk-...
model=gpt-4o-mini
system_prompt=You are Agent98...
extra_headers=X-Title: Agent98
stream=1
max_tokens=1024
temperature=0.7
[agent]
workspace=C:\Agent98
allow_shell=0
; 0 = no limit (stop with the GUI Stop button), otherwise 1..200
max_steps=32
[tls]
verify=1
[log]
level=3
```

`workspace` defaults to the `workspace` folder next to the executable. The log
is written to `agent98.log` in the same directory.

#### GUI settings

`Tools -> Settings...` edits every API parameter:

- **Provider** presets: OpenAI, DeepSeek, Moonshot/Kimi, SiliconFlow, Ollama
  (local), Custom. Picking a preset fills in the API base and default model.
- **API base / API key / Model**: any OpenAI-compatible service; the key may be
  empty for Ollama.
- **System prompt**: multi-line system prompt.
- **Temperature / Max tokens / Max steps**: steps may be 0 (no limit) or any
  value from 1 to 200.
- **Extra headers**: one `Name: value` per line, or several separated by `|` on
  one line, for services such as OpenRouter that need extra headers.
- **Test connection**: sends a GET to `{api_base}/models` and shows the HTTP
  status. 401/403 means a key problem, 404 an address problem, 5xx means the
  server is reachable but failing.
- **Workspace / TLS / shell / stream** toggles.

All fields are saved to `agent98.ini`.

#### GUI features

The 800x600 GUI keeps a 90s console look:

- The transcript uses a 9 pt fixed-pitch font (Fixedsys, or NSimSun on CJK
  systems) and colour-codes the conversation: `You:` in bold dark blue,
  `[round]` grey, `[tool]` teal, `[result]` green and `[error]` red.
- The **History** combo box at the top lists the sessions in `sessions/`
  (next to the executable). Every completed request is saved automatically as
  `YYYYMMDD_HHMM_<first prompt>.json`; selecting an entry reloads it and
  **New** starts a fresh conversation.
- `Alt+Up` / `Alt+Down` in the input box cycle the prompts from this run
  (DOSKEY style).
- **File -> Export transcript...** (`Ctrl+E`) writes the visible transcript as
  CP_ACP text with CRLF line endings, ready for Notepad.
- The native status bar shows a spinner and the current round while a request
  runs, plus the workspace path.
- **Tools -> Open workspace** (or the **Workspace** button) opens the workspace
  folder in Explorer.

#### Agent loop and loop guard

One user turn is a loop of API rounds followed by tool execution. `max_steps`
bounds the number of tool rounds; the default is 32, and `0` means unlimited,
so the run continues until the model answers or the user presses **Stop**
(Ctrl+C in the CLI). The GUI and INI accept 0 or 1..200.

A high or unlimited limit is safe because a loop guard watches the tool calls.
If the model sends the same tool name with the same arguments three times in a
row, the third call is not executed: the model receives an error tool result
asking it to change approach or finish. A fourth identical call stops the run
with `loop guard stopped the run`, which protects the API quota. Every blocked
call still gets a tool message, so the saved history stays protocol-valid.

#### Network retries and text encoding

`api_chat` retries transient failures up to twice (1 s, then 2 s backoff):

- connection failures and TLS read errors
- HTTP 429 / 502 / 503 / 504

Every retry is logged to `agent98.log` at WARN level. If part of a streamed
answer has already been displayed, no retry happens, so text is never
duplicated; Ctrl+C still cancels immediately during the backoff.

`write_file` converts the model's UTF-8 content to the local ANSI code page
(CP_ACP, GBK on a Simplified Chinese system) so Notepad, EDIT and
`COMMAND.COM` display it correctly, and falls back to raw UTF-8 when the code
page cannot represent a character. It also normalises bare `\n` to DOS `\r\n`
without doubling an existing `\r\n`, which is what lets a generated `.BAT` /
`.CMD` run line by line under the 16-bit `COMMAND.COM` of Windows 9x. Binary
extensions such as `.EXE`, `.DLL` and `.ZIP` keep their exact bytes.

`read_file` validates the bytes first: valid UTF-8 is returned as is (a UTF-8
BOM is dropped), while anything else is treated as CP_ACP and converted to
UTF-8, so the model can read files produced by Win9x applications without
mojibake.

#### Runtime environment injection

Every request gets a probe block prepended to the system message, followed by
the user's system prompt as `User instructions`:

- the OS version from `GetVersionExA`, e.g.
  `Windows 98 Second Edition 4.10.2222 A`
- the current workspace and process working directory
- hard constraints: `run_command` uses 16-bit `COMMAND.COM`, not `cmd.exe` or
  PowerShell; no `2>&1`, `&&`, `||`, stderr pipes, `curl` or `tasklist`; prefer
  the built-in file tools and `ver`, `mem`, `dir`, `set`, `type`

This stops the model from suggesting PowerShell commands that cannot run on
Windows 9x. The block needs no configuration and cannot be disabled from the
INI file.

### Testing

#### TLS probe

```bat
build\ow\tlsprobe.exe https://example.com/
```

It prints the TLS version, cipher suite and HTTP status.

#### Mock server

```bat
node tests\mock_openai.js 8787
```

Point `api.base` in `build/testrun/agent98.ini` at
`http://127.0.0.1:8787/v1`; `key` can be `test`. Sending `retry 503` or
`retry drop` makes the server fail the first request with 503 or drop the
connection, which exercises the retry logic. `loop forever` repeats the same
tool call every round (loop guard), while `count up 40` issues 40 distinct
calls and then answers (unlimited steps).

The script starts its own mock server: the first request returns 503 (or the

Using the mock server on port 8791, the script verifies that `max_steps=0`

```powershell

    build\ow\a98.exe build\ow\agent98.exe build\ow\tlsprobe.exe
```

It verifies image base 0x400000, stripped relocations, subsystem version 4.0,
the 256 KB stack, and that no NT-only DLL is imported. Everything must PASS

### Known limitations

- Only OpenAI-compatible APIs are implemented; Anthropic / Gemini are not wired up
- On Windows 9x the GUI falls back from RichEdit 2.0A to RichEdit 1.0 / EDIT
  when the newer control is unavailable
- No proxy support and no context trimming yet
- Closing the window waits up to 3 seconds for the worker; the timeout path
  still needs hardening

#### 多线程运行时（重要）

GUI 的 worker 线程会调用 C 运行时（malloc、stdio、日志等）。OpenWatcom
必须使用多线程运行时，并且新线程必须由 CRT 创建：

- 编译选项包含 `-bm`（见 `ow/rules.mk` 中的 `PROJECT_CFLAGS`）
- 使用 `_beginthreadex()`，不要直接使用 `CreateThread()`

否则 CRT 不会为新线程初始化 per-thread 数据，堆操作会随机崩溃
（`0xC0000005`，崩溃位置通常在 `__MemAllocator`）。

#### Win9x 链接选项

`tools/gen_ow_build.ps1` 生成的所有 wlink 响应文件都带有：

```
option offset=0x400000
option norelocs
option version=4.0
option stack=262144
```

固定基址、去掉重定位表、镜像版本 4.0，Win9x 的 PE 加载器才愿意加载；
256 KB 栈给 BearSSL 客户端上下文留足空间。改动这些选项后需要重新运行
`tools\gen_ow_build.ps1`，再 `build_ow.cmd clean` 全量重建。

#### GUI 功能

- 顶部的 **History** 下拉框列出 exe 同目录 `sessions/` 中的会话。每次请求

- **Tools -> Open workspace**（或 **Workspace** 按钮）在资源管理器中打开

#### Agent 循环与死循环保护

一轮用户对话由多次 API 请求和工具执行组成。`max_steps` 限制工具轮数，默认
32；填 0 表示不限，直到模型给出最终回答或用户点击 **Stop**（CLI 中按
Ctrl+C）。GUI 和 INI 都接受 0 或 1~200。

上限调高或设为不限后，由循环保护（Loop Guard）兜底：如果模型连续 3 次用
完全相同的工具名和参数调用，第 3 次不再执行，而是把错误结果返回给模型，
要求它更换方案或直接结束；如果第 4 次仍然完全重复，则终止本轮对话并报
`loop guard stopped the run`，避免空转消耗 API 额度。被拦截的调用仍会写入
一条 tool 消息，因此保存的会话历史始终符合协议格式。

#### 网络重试与文本编码

`api_chat` 对瞬时故障自动重试，最多 2 次（1 秒、2 秒退避）：

- 连接失败、TLS 读错误等网络层错误
- HTTP 429 / 502 / 503 / 504

每次重试都会写入 `agent98.log`（WARN 级别）。如果流式回复已经把部分文字
显示出来，就不再重试，避免内容重复；退避期间按 Ctrl+C 也能立即取消。

`write_file` 会把模型传入的 UTF-8 文本转换为系统当前代码页（CP_ACP，
简体中文下为 GBK）再落盘，这样 Win98/Me 的记事本、EDIT 和 `COMMAND.COM`
都能正确显示；如果遇到当前代码页无法表示的字符，则回退为原始 UTF-8。
同时把孤立的 `\n` 规范化为 DOS 的 `\r\n`，已有的 `\r\n` 不会重复转换，
保证生成的 `.BAT` / `.CMD` 能在 16 位 `COMMAND.COM` 下逐行执行。
`.EXE`、`.DLL`、`.ZIP` 等二进制扩展名保持原始字节。

`read_file` 先校验内容是否为合法 UTF-8：是则原样返回（并去掉 UTF-8 BOM），
否则按 CP_ACP 解码后再转成 UTF-8 交给模型，因此读取 Win9x 本地程序生成的
GBK 文件也不会乱码。

#### 运行时环境注入

每次请求都会在 system 消息最前面自动加入一段探测结果，再把用户填写的
system prompt 作为 `User instructions` 追加在后面：

- 通过 `GetVersionExA` 识别的系统版本，例如
  `Windows 98 Second Edition 4.10.2222 A`
- 当前 workspace 和进程工作目录
- 核心约束：`run_command` 使用 16 位 `COMMAND.COM`，不是 `cmd.exe`
  或 PowerShell；不要使用 `2>&1`、`&&`、`||`、stderr 管道、`curl`、
  `tasklist`，优先使用内置文件工具和 `ver`、`mem`、`dir`、`set`、`type`

这样模型不会在 Win9x 上建议无法执行的 PowerShell 命令。该段内容不需要
配置，也不能通过 INI 关闭。
